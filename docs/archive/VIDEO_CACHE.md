# 🚀 视频缓存功能说明

## ✅ 功能实现

现在系统支持视频缓存功能！相同的视频文件再次上传时会自动识别并跳过处理。

## 🔑 工作原理

### 1. 文件识别

通过计算视频文件的 **MD5 hash** 来唯一识别文件：
- 相同内容的文件 → 相同的 hash
- 不同内容的文件 → 不同的 hash

### 2. 缓存检查流程

```
上传视频
  ↓
计算文件 Hash
  ↓
查找是否存在相同 Hash 的视频
  ↓
├─ 找到缓存 → 直接返回已有结果（秒级响应）
└─ 未找到 → 执行完整处理（分钟级）
```

### 3. 缓存命中

当再次上传 **相同的视频** 时：

```
========== 开始处理视频: examlpe_video.mp4 ==========

[0/4] 正在检查视频缓存...
文件 Hash: 5f4dcc3b5aa765d61d8327deb882cf99
✅ 找到缓存视频: examlpe_video.mp4
   视频 ID: abc-123-def
   跳过处理，直接使用缓存结果

========== ✅ 使用缓存，跳过处理 ==========
```

**处理时间**：从 **2-5分钟** 降到 **< 1秒** ⚡

## 💾 数据存储

### 视频数据结构

```json
{
  "id": "abc-123-def",
  "filename": "examlpe_video.mp4",
  "path": "uploads/examlpe_video.mp4",
  "duration": 120.5,
  "file_hash": "5f4dcc3b5aa765d61d8327deb882cf99",  // 新增：用于缓存
  "analysis": { ... },
  "transcript": [ ... ],
  "created_at": "2024-01-14T12:00:00"
}
```

### 缓存位置

- 视频信息：`data/videos/{video_id}.json`
- 每个视频的 JSON 文件包含 `file_hash` 字段
- 系统会遍历所有 JSON 文件查找匹配的 hash

## 🔍 缓存识别逻辑

### 什么时候会命中缓存？

✅ **会命中缓存**：
- 上传完全相同的视频文件
- 即使文件名不同，只要内容相同
- 即使在不同时间上传

❌ **不会命中缓存**：
- 视频内容有任何改动（哪怕1个字节）
- 不同的视频文件
- 被编辑过的视频（即使只是裁剪）

### 示例

```bash
# 场景 1：完全相同的文件
上传 video1.mp4 (内容: A)  → 完整处理
再次上传 video1.mp4 (内容: A)  → ✅ 使用缓存

# 场景 2：内容相同但文件名不同
上传 video1.mp4 (内容: A)  → 完整处理
上传 video2.mp4 (内容: A)  → ✅ 使用缓存（内容相同）

# 场景 3：文件名相同但内容不同
上传 video.mp4 (内容: A)  → 完整处理
上传 video.mp4 (内容: B)  → ❌ 完整处理（内容不同）
```

## 🛠️ 代码修改说明

### 修改的文件

1. **storage.py**
   - 新增 `calculate_file_hash()` - 计算文件 hash
   - 新增 `find_video_by_hash()` - 通过 hash 查找视频

2. **video_service.py**
   - 修改 `process_upload()` - 添加缓存检查逻辑
   - 保存视频时添加 `file_hash` 字段

### 关键代码

```python
# 计算文件 hash
file_hash = Storage.calculate_file_hash(file_path)

# 查找缓存
cached_video = Storage.find_video_by_hash(file_hash)

if cached_video:
    # 使用缓存，跳过处理
    return {
        "video_id": cached_video["id"],
        "duration": cached_video["duration"],
        "analysis": cached_video.get("analysis", {}),
        "cached": True
    }
```


